TACHYON 정책 마이그레이션 (tkctl tachyon migrate-policies)

TACHYON 신 버전 패키지 업데이트 직후 정책 데이터를 신 스키마로 변환하는 운영 명령입니다.

미실행 시 위험

신 버전이 구 형식 정책을 읽을 때 정책 미적용 또는 parsing 오류 발생 가능 → 매체제어 / 방화벽 / Self-defense 등 보안 정책 무력화 위험. TACHYON 패키지 업데이트 후 본 명령을 반드시 실행하세요.

사용 시점​

시점명령 (v0.8.1 default env-token mode)
TACHYON 패키지 업데이트 후 (서비스 재시작 직후)TACHYON_AUTH_TOKEN=... tkctl tachyon migrate-policies --sp-code <code>
패키지 후속 정책 미반영 의심 시 (재실행 안전, idempotent)동일 명령 재실행
v0.8.1 Breaking Change

v0.8.1 부터 default 인증 모드가 placeholder → env-token 으로 변경되었습니다. 토큰을 TACHYON_AUTH_TOKEN env / --auth-token-file / TTY stdin prompt 중 하나로 명시 주입해야 합니다. BL-039 v0.6.38 호환은 §6.3 마이그레이션 가이드 참조.

표준 명령 (v0.8.1)​

SP_CODE="00326FDH6DX"  # 사이트의 TACHYON 고객사 코드

# 권장: secrets manager 통합 (HashiCorp Vault / AWS SSM / Azure Key Vault)
TACHYON_AUTH_TOKEN="$(vault kv get -field=token secret/tachyon)" \
    sudo -E tkctl tachyon migrate-policies \
        --sp-code "$SP_CODE" \
        --report-file "/var/log/tachyon/migrate-$(date +%s).json"

# 또는 token 파일 (0600 강제)
sudo tkctl tachyon migrate-policies \
    --sp-code "$SP_CODE" \
    --auth-token-file /etc/tkadmin/tachyon-token \
    --report-file "/var/log/tachyon/migrate-$(date +%s).json"
sudo -E 옵션

TACHYON_AUTH_TOKEN 같은 env 변수를 sudo 환경으로 전파하려면 -E 플래그가 필요합니다. token 파일 방식은 sudo 환경 변수 전파가 불요라 더 단순.

기대 출력:

[tachyon] policy migration 시작 — sp-code=00326FDH6DX types=7
[tachyon] 완료 — total=7 success=7 failed=0 skipped=0 (12450ms)
  ✓ AGENT — HTTP 200 (1820ms)
  ✓ ENDPOINT — HTTP 200 (2014ms)
  ✓ MEDIA — HTTP 200 (1655ms)
  ✓ SELF — HTTP 200 (1432ms)
  ✓ FIRE_WALL — HTTP 200 (2010ms)
  ✓ UMS — HTTP 200 (1721ms)
  ✓ ASSET — HTTP 200 (1798ms)
[tachyon] 보고서 저장: /var/log/tachyon/migrate-1714849800.json

지원하는 정책 타입 (의존성 안전 순)​

순서Type도메인
1AGENTTACHYON Agent 자체 설정 (heartbeat, 자동 업데이트)
2ENDPOINT단말 (PC) 보안 정책
3MEDIA매체제어 (USB / 외장 디스크 / 광학 / 모바일)
4SELFSelf-defense (Agent 자기보호)
5FIRE_WALLTACHYON Firewall (네트워크 ACL)
6UMSUnified Management/Media Security
7ASSET자산 관리 (HW/SW 인벤토리)
병렬 호출 금지

본 명령은 순차 호출을 보장합니다. 정책 간 FK / 참조 무결성 충돌 가능성 때문에 7개 타입을 동시에 호출하면 안 됩니다.

옵션 (v0.8.1)​

Flag기본값설명
--sp-code(필수)TACHYON 고객사 코드
--base-urlhttp://localhost:13601TACHYON API base URL
--auth-methodenv-token인증 방식: env-token (default, secrets manager 통합) | placeholder (BL-039 호환, deprecated)
--auth-token-file(없음)env-token mode 의 token 파일 경로 (0600 강제, env 와 동시 지정 불가)
--auth-token(없음)placeholder mode 만 사용. env-token mode 에서 사용 시 에러 (shell history 누출 방지)
--yes-i-accept-riskfalseplaceholder mode 강제 ack — 보안 결함 인수 명시 필수
--types(전체 7)마이그레이션할 정책 타입 (CSV)
--timeout30s각 호출 timeout
--continue-on-errortrue한 타입 실패 시 다음 타입 계속
--report-file(없음)결과 JSON 보고서 저장 경로
--dry-runfalse실 호출 없이 호출 계획만 출력
env-token mode 입력 우선순위
  1. TACHYON_AUTH_TOKEN env var (priority 1)
  2. --auth-token-file <path> (priority 2, 0600 강제)
  3. stdin prompt (priority 3, TTY 만 + echo off)

env + file 동시 지정은 audit 추적성 보호를 위해 차단됩니다.

자주 사용하는 시나리오​

1. 일부 타입만 재시도 (이전 보고서에서 실패한 타입)​

tkctl tachyon migrate-policies \
    --sp-code "$SP_CODE" \
    --types MEDIA,FIRE_WALL

2. Dry-run 으로 호출 계획 검증​

tkctl tachyon migrate-policies --sp-code "$SP_CODE" --dry-run
[DRY-RUN] sp-code=00326FDH6DX base-url=http://localhost:13601
[DRY-RUN] would call 7 policy types in order:
  1. AGENT
  2. ENDPOINT
  ...
  7. ASSET

3. 첫 실패 시 즉시 중단 (운영 점검 모드)​

tkctl tachyon migrate-policies \
    --sp-code "$SP_CODE" \
    --continue-on-error=false

4. 보안 토큰을 env 로 주입 (CI / Ansible / GitOps 통합)​

TACHYON_AUTH_TOKEN="$(vault kv get -field=token secret/tachyon/migrate)" \
    tkctl tachyon migrate-policies --sp-code "$SP_CODE"

결과 보고서 (JSON)​

--report-file 지정 시 또는 stdout 으로 출력:

{
  "sp_code": "00326FDH6DX",
  "base_url": "http://localhost:13601",
  "started_at": "2026-05-04T22:30:00Z",
  "completed_at": "2026-05-04T22:30:14Z",
  "duration_ms": 14000,
  "types": [
    {"type": "AGENT", "status": "success", "http_code": 200, "duration_ms": 1820},
    {"type": "MEDIA", "status": "failed", "http_code": 500, "error": "HTTP 500", "duration_ms": 3023}
  ],
  "summary": {"total": 7, "success": 6, "failed": 1, "skipped": 0}
}
보안 보장

보고서 JSON 에 auth_token 등 민감 헤더 값은 절대 포함되지 않습니다. 운영자는 보고서를 audit / 회귀 추적 용도로 안전하게 영구 보관 가능합니다.

종료 코드​

코드의미
0모든 타입 성공
1한 개 이상 실패 (failed > 0) — 보고서 확인 후 재시도 권장

자동화 스크립트 (Ansible, GitOps) 에서는 종료 코드 1 을 failed_when 또는 until 분기 조건으로 활용 가능합니다.

운영 통합 예시 (Ansible)​

- name: TACHYON 정책 마이그레이션
  command: >
    tkctl tachyon migrate-policies
    --sp-code {{ tachyon_sp_code }}
    --report-file /var/log/tachyon/migrate-{{ ansible_date_time.epoch }}.json
  environment:
    TACHYON_AUTH_TOKEN: "{{ vault_tachyon_migrate_token }}"
  register: result
  failed_when: result.rc != 0
  changed_when: "'failed=0' not in result.stdout or 'success=7' in result.stdout"

트러블슈팅​

--sp-code is required​

--sp-code 또는 환경 변수로 사이트 고객사 코드를 반드시 지정해야 합니다. 사이트별 코드는 TACHYON 운영팀에 확인하세요.

HTTP 500 / HTTP 502 응답​

TACHYON 서비스 부팅 직후 또는 DB 마이그레이션 진행 중일 수 있습니다. 30초~1분 후 재시도하세요. 반복적으로 발생하면 TACHYON 본 제품의 application log (/var/log/tachyon/) 를 확인합니다.

context deadline exceeded​

--timeout 기본 30초 초과. 정책 데이터가 많은 사이트에서는 --timeout 120s 등으로 확장 가능합니다.

부분 실패 후 재시도​

기본 --continue-on-error=true 모드에서 일부 타입만 실패한 경우, 보고서의 types[].status='failed' 항목만 추출하여 --types 로 재실행:

# 보고서에서 실패 타입 추출
FAILED=$(jq -r '.types[] | select(.status=="failed") | .type' /var/log/tachyon/migrate-*.json | tr '\n' ',' | sed 's/,$//')
# 재시도
tkctl tachyon migrate-policies --sp-code "$SP_CODE" --types "$FAILED"

6. 인증 모드 (BL-040 v0.8.1)​

BL-039 호환성 변경 (Breaking Change)

v0.8.1 부터 default 인증 모드가 placeholder 에서 env-token 으로 변경되었습니다. BL-039 운영자는 §6.3 마이그레이션 가이드 1회 적용 필요.

6.1 인증 모드 비교​

모드사용 시보안 수준BL 표적
env-token (default)운영 표준 — secrets manager 통합⭐⭐⭐BL-040 v0.8.1
placeholderBL-039 호환 (deprecated 예정)⭐BL-039
mtls (보류)실 구현 BL-040c 후속⭐⭐⭐⭐BL-040c
jwt (보류)TACHYON Auth Service 자동 발급 BL-040b 후속⭐⭐⭐BL-040b

6.2 env-token mode 입력 우선순위 (default)​

1. TACHYON_AUTH_TOKEN env var          (priority 1)
2. --auth-token-file <path> (0600 강제)  (priority 2)
3. stdin prompt (TTY only, echo off)     (priority 3)

동시 지정 금지: env + file 동시 사용 시 명확한 에러 (audit 추적성 보호).

6.2.1 secrets manager 통합 패턴 (권장)​

# HashiCorp Vault
TACHYON_AUTH_TOKEN="$(vault kv get -field=token secret/tachyon)" \
    tkctl tachyon migrate-policies --sp-code 00326FDH6DX

# AWS Secrets Manager
TACHYON_AUTH_TOKEN="$(aws secretsmanager get-secret-value \
    --secret-id tachyon/migrate-token --query SecretString --output text)" \
    tkctl tachyon migrate-policies --sp-code 00326FDH6DX

# Azure Key Vault
TACHYON_AUTH_TOKEN="$(az keyvault secret show \
    --vault-name MyVault --name tachyon-migrate-token --query value -o tsv)" \
    tkctl tachyon migrate-policies --sp-code 00326FDH6DX

# 1Password CLI
TACHYON_AUTH_TOKEN="$(op read 'op://Vault/tachyon/token')" \
    tkctl tachyon migrate-policies --sp-code 00326FDH6DX

6.2.2 token 파일 사용​

# 0600 권한 강제 (운영자 책임)
echo -n "operator-token-xyz" > /etc/tkadmin/tachyon-token
chmod 0600 /etc/tkadmin/tachyon-token

tkctl tachyon migrate-policies \
    --sp-code 00326FDH6DX \
    --auth-token-file /etc/tkadmin/tachyon-token
0600 권한 강제

--auth-token-file 의 권한이 0600 이 아니면 즉시 거부됩니다 (group/world readable 차단). chmod 0600 <path> 로 정정.

6.2.3 대화형 stdin prompt (TTY 만)​

$ tkctl tachyon migrate-policies --sp-code 00326FDH6DX
TACHYON auth token: ********  # echo off (golang.org/x/term)
[tachyon] policy migration 시작 ...

CI / 비대화형 환경 (stdin not a tty) 에서는 즉시 fail. 자동화 스크립트는 env 또는 file 사용 필수.

6.3 BL-039 placeholder 마이그레이션 가이드​

v0.6.38 (BL-039) 의 default placeholder 의존 운영자는 다음 중 한 경로로 전환:

권장: secrets manager 표준화 (운영자 인프라)​

# Before (BL-039)
tkctl tachyon migrate-policies --sp-code "$SP_CODE"  # placeholder=1234 묵시 사용

# After (BL-040 v0.8.1)
TACHYON_AUTH_TOKEN="$(vault kv get -field=token secret/tachyon)" \
    tkctl tachyon migrate-policies --sp-code "$SP_CODE"

대안: token 파일​

# 1회 setup
echo -n "your-real-token" | sudo tee /etc/tkadmin/tachyon-token >/dev/null
sudo chmod 0600 /etc/tkadmin/tachyon-token

# After
tkctl tachyon migrate-policies --sp-code "$SP_CODE" \
    --auth-token-file /etc/tkadmin/tachyon-token

비권장: 의식적 placeholder 유지​

# 보안 결함 의식적 인수 (--yes-i-accept-risk 명시 필수)
# BL-040b/c 후속에서 deprecated 예정.
tkctl tachyon migrate-policies --sp-code "$SP_CODE" \
    --auth-method=placeholder \
    --yes-i-accept-risk \
    --auth-token=1234
placeholder mode 보안 결함

placeholder mode 는 BL-040 명시적으로 격리된 호환 경로입니다. 보고서에 accepted_risk: true 가 audit 기록되어 운영자 의식적 인수가 추적 가능. 신 운영 환경에서는 §6.2 secrets manager 또는 token 파일 권장.

6.4 audit Report 신규 필드​

v0.8.1 부터 보고서 JSON 에 다음 필드 추가:

env-token mode (default — accepted_risk 는 omitempty 로 미포함):

{
  "auth_method": "env-token",
  "auth_source": "env",
  "token_fingerprint": "a1b2c3d4",
  ...
}

placeholder mode (의식적 ack 명시 시):

{
  "auth_method": "placeholder",
  "auth_source": "placeholder",
  "accepted_risk": true,
  "token_fingerprint": "03ac674a",
  ...
}
필드의미
auth_method인증 모드 (placeholder / env-token)
auth_source토큰 source (placeholder / env / file / stdin)
accepted_riskplaceholder mode 강제 ack 여부 (omitempty — env-token mode 에서는 필드 자체 미출력)
token_fingerprintSHA-256 첫 4 bytes hex (8자) — 평문 노출 0, 회전 추적 힌트. 고유 audit key 가 아님 (32-bit fingerprint 는 birthday paradox 충돌 가능 + placeholder 같은 wide-spread token 은 rainbow table 추정 위험). 정밀 추적은 BL-040b auth_subject (username) 활용 예정

보안 보장: 평문 토큰 / 비밀번호 / 인증서 경로는 보고서에 절대 미포함.

6.5 mTLS 옵션 (BL-040c 보류)​

mTLS 실 구현은 TACHYON 본 제품의 nginx client cert verify 활성 가능 여부 (EX-3 외부 협의) + 마이그레이션 엔드포인트 인증 검증 정책 (EX-2 외부 협의) 확인 후 BL-040c 에서 진행 예정. 본 BL-040 에서는 설계 SSOT 만 docs/spec/18_tachyon_migrate.md §18.9.4 에 보존.

  • 변경 이력: CHANGELOG v0.6.38 (BL-039) + v0.8.1 (BL-040)
  • Plan SSOT: docs/plans/security/PLAN_BL040_TACHYON_SECURE_VAULT.md

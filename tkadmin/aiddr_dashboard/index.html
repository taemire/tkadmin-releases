27. AI DDR 대시보드

27.1 개요​

AI DDR 대시보드는 N²SF AI 기반 데이터 분류·등급(C/S/O)·정책 가이드 운영을 한 화면에서 수행할 수 있도록 위젯 5종을 통합 제공합니다 (BL-026).

  • 사이드바 → 관측 섹션 → AI DDR 대시보드 항목으로 진입합니다.
  • 모든 위젯은 단일 페이지에서 비동기 부트스트랩되며, F5 새로고침 시 마지막 필터 상태를 sessionStorage 에서 복원합니다.
정보

AI DDR 대시보드는 백엔드 LogAI 파이프라인(BL-023)과 PolicyGuide 모듈(BL-024)이 활성화되어 있어야 데이터가 채워집니다. LogAI 비활성 환경에서는 각 위젯이 빈 상태(empty placeholder) 또는 인라인 오류로 표시됩니다.

27.2 위젯 구성 (6종)​

27.3 위젯별 상세​

27.3.1 C/S/O 분포 도넛​

  • 일/주/월 토글로 조회 범위를 전환합니다.
  • 도넛 SVG 는 색상 + 패턴(C: 단색, S: 사선 빗금, O: 점 패턴) + sr-only 표 를 동시에 제공해 색맹 사용자도 등급을 구별할 수 있습니다 (WCAG AA 대비 ≥ 4.5:1).
  • 데이터 0건일 때는 "표시할 분류 결과가 없습니다." 빈 상태가 표시됩니다.

27.3.2 위험 사용자 Top​

  • 등급별 합계가 많은 사용자를 표로 제공합니다.
  • 사용자 ID 는 HMAC-SHA256 hash 의 앞 8자(prefix)만 표시됩니다 (G8 마스킹 정책). 64자 raw HMAC 은 절대로 응답·DOM 어디에도 노출되지 않으며, 프론트엔드 가드 정규식이 응답을 검증합니다.
  • limit 입력은 1~100 범위로 클램핑됩니다 (서버 측 검증과 클라이언트 측 검증 이중 방어).

27.3.3 PolicyGuide 검토​

  • 상태 필터(전체/draft/applied/rejected/expired)로 정책 가이드를 조회합니다.
  • "YAML 보기" 버튼은 Monaco editor 를 read-only 모드로 띄우며 (domReadOnly: true, accessibilitySupport: 'on'), Monaco 미가용 환경에서는 <pre> fallback 으로 동일한 aria-label 이 적용됩니다.
  • 적용/기각 버튼은 draft 상태 + manage:aiddr 권한 보유 시에만 활성화됩니다.
  • 적용/기각 시 확인 모달 (focus trap + Esc 닫기) 이 노출되며, 기각은 사유(선택) 입력을 받을 수 있습니다.

27.3.4 임계값 보정​

  • 활성(effective) 임계값과 변경 이력을 분리해 표로 제공합니다.
  • 임계값 변경 폼은 manage:aiddr 미보유 사용자에게는 disabled 상태로 렌더링됩니다.
  • 값 변경 시 확인 모달이 노출되고, 성공 시 audit 이력에 새 행이 추가됩니다.

27.3.5 운영자 피드백​

  • finding 목록에 대해 운영자가 TP / FP / Unknown 판정(verdict)을 기록할 수 있습니다.
  • 상단의 분기 통계 그리드(TP / FP / Unknown / 합계)는 verdict 변경 시 자동으로 재집계됩니다.
  • finding 행의 사용자 컬럼도 8자 prefix 만 표시되며, 64자 hex 노출은 응답 단계에서 차단됩니다.

27.3.6 알림 파이프라인 지연시간 (BL-033)​

  • BL-027 외부 SIEM 알림 파이프라인의 wall-clock latency 를 운영자가 5초 단위로 모니터링할 수 있는 위젯입니다.
  • 측정점:
    • T0: finding 결정 시각 (AlertEvent.OccurredAt)
    • T1: Dispatch() 진입 시각 (큐 enqueue 직전)
    • T2: Sink.Send 종료 시각 (외부 syslog/CEF/webhook 또는 audit 송신 완료)
  • 표시 메트릭 (60 슬롯 × 5초 = 5분 sliding window):
    • P50/P95/P99 (T2-T0): 전체 지연 분포. NFR 게이트는 P95 ≤ 60s.
    • Queue wait P95 (T1-T0): 큐 대기 시간 분포. SinkRouter worker pool 포화 진단용.
    • Send P95 (T2-T1): 실제 sink 송신 시간 분포. 외부 SIEM 응답 지연 진단용.
  • 카운터: Dispatched / Queue full drops / Send 성공 / Send 실패 (실패 또는 drop ≥1 시 빨간 색상 강조)
  • 상태 pill (3종):
    • 정상 (초록): 활성 + sample ≥ 1건 — 정상 운영
    • 샘플 없음 (주황): 활성이지만 5분 윈도우 내 finding 송신 0건 — finding 발생 자체가 없음
    • 비활성 (회색): alert.enabled=false 또는 router 미구성 — 설정 점검 필요
  • 임계치 pill (4종, WCAG AA 4.5:1 색맹 안전 — 색+아이콘+텍스트 동시):
    • 정상 (≤ 48s) ✓ 초록 — NFR 80% margin 권고 범위
    • 주의 (48~60s) ⚠ 주황 — NFR 60s 한계 근접 (운영 점검 권고)
    • 초과 (> 60s) ✗ 빨강 — NFR 위반 (즉시 sink 상태/네트워크 점검)
    • 데이터 없음 – 회색 — 샘플 없음 또는 비활성 상태
  • 최근 샘플 (10건): Finding Hash (HMAC-SHA256 32자, 영구 식별자 아님 — 프로세스 재시작 시 회전) / 큐 대기 (T1-T0, ms) / 총 지연 (T2-T0, ms) / Sink (audit/syslog/webhook/cef) / 결과 (success/failure/timeout)

진단 시나리오​

증상의미운영자 조치
초과 (> 60s) 빨간 pill + Queue wait P95 ≪ Send P95외부 SIEM 자체 응답 지연SIEM 인프라 (syslog 서버 / webhook 엔드포인트) 상태 점검
초과 (> 60s) 빨간 pill + Queue wait P95 ≫ Send P95SinkRouter worker pool 포화alert.workers 설정값 증가 또는 alert.queue_size 확장
Queue full drops 카운터 ≥ 1큐 적체로 finding 일부 droppedalert.queue_size 즉시 확장 + 원인 분석 (외부 SIEM 다운 가능성)
Send 실패 카운터 ≥ 1 + 최근 샘플 failure/timeout외부 SIEM 일시 연결 실패retry 정책 동작 중 — 5분 후 자동 회복 또는 SIEM 인프라 점검

보안​

  • Finding Hash 는 HMAC-SHA256(서버 secret 32 byte, finding_id) 의 hex prefix 32자 — raw finding_id 는 노출되지 않음. 서버 secret 은 프로세스 부팅 시 crypto/rand 로 1회 생성 → finding_hash 가 영구 식별자가 되지 않도록 회전.
  • view:aiddr 권한 보유자 (admin / monitor / superadmin) 만 위젯 접근 가능. manage:aiddr 는 본 위젯에서 사용 안 함 (read-only).
  • 응답 캐시: 5초 TTL + singleflight + 30초 last-known-good grace fallback. backend 일시 실패 시 grace 동안 stale 응답 반환 + 서버 로그에 slog.Warn 1회 기록.

27.5 보안 정책​

27.5.1 G8 마스킹 (HMAC 64자 미노출)​

  • 백엔드 DTO 가 user_hmac_prefix 필드(8자) 만 직렬화하며, raw 64자 HMAC 은 응답에 포함되지 않습니다.
  • 프론트엔드도 응답을 DOM 에 주입하기 전 [a-f0-9]{64} 정규식 가드를 통과시키며, 위반 시 인라인 오류로 차단합니다.

27.5.2 POST 4종 보호​

  • apply / reject / thresholds/set / feedback 엔드포인트는 Bearer JWT 우선 + (쿠키 only 시) Origin/Referer 검증을 수행합니다.
  • 인증 실패는 401, 권한 부족은 403 으로 일관되게 응답합니다.

27.5.3 에러 sanitize​

  • 모든 오류 응답은 i18n 키 + 메시지만 외부에 노출하며, 내부 SQL 문/스택/파일 경로는 서버 로그(slog.Error) 에만 기록됩니다.

27.6 i18n / a11y​

  • 모든 텍스트는 tkadmin.aiddr.* i18n 키 경유 — 하드코딩 0.
  • 한국어/영어 i18n 파일은 동일 키 셋을 보유하며, internal/i18n 일관성 게이트가 자동 검증합니다.
  • 도넛 SVG 는 role="img" + aria-label (i18n 패턴: "기밀 N건, 민감 N건, 공개 N건, 합계 N건") + sr-only 표 보조를 제공합니다.
  • 모든 모달은 ESC 닫기 + 첫 입력 자동 포커스 + 트리거 버튼으로 포커스 복귀를 표준화합니다.

27.7 진단/문제 해결​

증상원인 추정조치
위젯이 모두 비어 있음LogAI 비활성 또는 데이터 미축적tkadmin.yml 의 ai.aiddr.enabled 확인 + BL-023 baseline 누적 대기
403 aiddr.error.permission_deniedRBAC 미보유관리자에게 view:aiddr / manage:aiddr 부여 요청
400 aiddr.error.invalid_range잘못된 range 파라미터day/week/month 중 하나로 토글
Apply/Reject 버튼이 회색manage:aiddr 미보유 또는 가이드가 draft 가 아님권한 확인 + status filter 를 draft 로 변경
Monaco 가 로드되지 않음정적 자원 누락static/lib/monaco/vs/loader.js 와 vs/editor/editor.main 모듈 확인
위젯 응답이 2초 이상V18 마이그레이션 미적용 또는 운영 row 100만+sqlite3 <db> 'PRAGMA user_version;' ≥18 확인. 부족 시 tkadmin 재기동(자동 마이그레이션). row 100만+ 시 BL-028b 진행

27.8 응답 시간 NFR (V18 인덱스 — BL-028 + BL-031 wall-clock 검증)​

Dashboard 위젯의 응답 시간 NFR 은 p95 ≤ 2초 입니다. v0.6.48(V18) 부터 다음 인덱스가 자동 적용됩니다:

인덱스정의대상 위젯
idx_logai_findings_observed_user_severitylogai_findings(created_at, user_hmac, severity) covering위험 사용자 Top + 운영자 피드백 시계열
idx_logai_policy_guides_created_idlogai_policy_guides(created_at, id) 정렬 인덱스PolicyGuide 검토

BL-028 SQL 측정 (시드 10만 row, SQLite 3.51.0): 모든 위젯 SQL < 0.06초 (NFR 33배 마진). 운영 row 100만 row 추정 시 인덱스 추가 디스크 ~100MB. EXPLAIN 확인 SQL 은 운영자 가이드 AI_LOGAI_GUIDE.md §8.12 참조.

BL-031 Playwright wall-clock 측정 (v0.6.49, BL-028 후속): 사용자 액션부터 DOM ready (+ rAF×N) 까지의 wall-clock 을 5 위젯 × 10회 측정. 게이트는 T_ui p95 ≤ 2,000ms.
